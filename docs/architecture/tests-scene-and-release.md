# Tests, test scene and releasing

Detail behind the corresponding bullets of the root `CLAUDE.md`.

## The test suite — `Assets/Tests/` (outside the package)

Added by `specs/05-performance-and-tests.md`. Lives outside `Packages/com.santiandrade.citygenerator/` on purpose, same reasoning as `Assets/Editor/CityGeneratorReleaseWindow.cs`/`CityGeneratorSetDefaultsWindow.cs`: it's a development tool for this repo, not something a user installing the package by git URL needs or expects. Three folders, each its own `.asmdef` referencing `CityGenerator.Runtime`/`CityGenerator.Editor`:

- **`EditMode/`** — `CityGeneratorGridTests` (blocks/plazas), `CityGeneratorDistributionUtilityTests` (percentage distribution), `CityGeneratorValidatorTests` (`ValidateDetailed`, including the SPEC 04 gaps and the SPEC 06 Custom Places checks), `TrafficNetworkRouteWeightTests` (`RouteWeight`/`Ring`), `PedestrianNetworkTests` (BFS via `FindPath`, `CanCross`, connected components). `EditMode/Generation/SeededGenerationTests.cs` runs full seeded generation on 1×3/5×5/10×10 grids, asserting no exceptions and basic invariants (block/building/network-node counts) — this is what confirms the SPEC 05 performance changes never altered placement output for a given seed. `EditMode/Generation/CustomPlaceBuilderTests.cs` (SPEC 06) does the same for a quarter-block and a whole-block Custom Place entry, asserting the reserved slot(s) are excluded from `CityGeneratorBuildingBuilder`'s random distribution and that the entry lands in `obstacles`.
- **`PlayMode/`** — `TrafficLightIntersectionCycleTests` (phase cycle), `PedestrianCanCrossTests` (red-only crossing), `ManagerRegistrationTests` (`TrafficManager`/`PedestrianManager` registration/deregistration, including re-`SetActive` reactivation), `PedestrianRoadProximityGridTests`, and `ColliderOnChildDetectionTests` (the SPEC 04 fix, automated instead of manual QA).
- **`Performance/`** — uses `com.unity.test-framework.performance` (a dependency of this project's `manifest.json`, not of the package's `package.json`, since the tests live outside it): `GenerationPerformanceTests` (generation time / `GC Alloc` per grid size) and `RuntimePerformanceTests` (frame cost via `Measure.Frames` at 60/150/300 combined vehicles+pedestrians). This suite caught a real regression during SPEC 05 (an `IndexOutOfRangeException` from `PedestrianNetwork`'s connected-components array falling out of sync with a POI-grown node list) — **treat a Performance test failure as a correctness signal, not noise.** Baseline and delta numbers for every SPEC 05 change are recorded in `specs/05-performance-and-tests.md`.

No CI integration exists — these run manually from the Unity Test Runner (`Window > General > Test Runner`), same as any other Editor workflow in this project.

## The test scene — `Assets/Scenes/City.unity`

A 5×5 city generated by the tool with default settings (`gridWidth`/`gridHeight` 5, `vehicleCount` 80, `pedestrianCount` 90), plus a `Player` instance placed on the shared `Pedestrian` layer, both at the scene root next to the `City` root's group empties (`Vehicles`/`TrafficNetwork`, `Pedestrians`/`PedestrianNetwork`, and the `CustomPlaces` group with the demo's whole-block `Hospital` entry at block `(3, 3)`). Static flags are set on every generated group except `Vehicles`/`Pedestrians`. Occlusion culling **is** baked (`Assets/Scenes/City/OcclusionCullingData.asset`); lightmaps are not. That per-scene folder — the one Unity itself creates next to a scene — also holds `City_Minimap.png`, the snapshot `CityGeneratorMinimapBuilder.SaveSnapshotAsset` writes (see `editor-tool.md`).

Build Settings list this scene as the only enabled one. It is **disposable**: regenerate it rather than repairing it, and never hand-edit it to fix something the tool should be doing.

## Versioning and releasing the package

- `Packages/com.santiandrade.citygenerator/package.json` carries the SemVer `version` (currently 2.4.1); `CHANGELOG.md` in the same folder follows Keep a Changelog, with a `## [Unreleased]` section always present above the latest release. A git tag `vX.Y.Z` marks each release.
- Unity has **no real "Update" button for a package installed by git URL** — installing fixes the resolved commit in `Packages/packages-lock.json`. Updating means reinstalling the URL with the new tag; this is documented for end users in the root README.
- `Assets/Editor/CityGeneratorReleaseWindow.cs` (`Tools > City Generator > Release`, outside the package, in `Assembly-CSharp-Editor`) automates the repetitive part: bumps `version` in `package.json`, turns `## [Unreleased]` into `## [X.Y.Z] - YYYY-MM-DD` and opens a new empty `## [Unreleased]` above it, then shows (and copies to the clipboard) the `git tag vX.Y.Z && git push origin vX.Y.Z` command. It never runs git itself — the tag is always created by a person, on purpose.
